#3 核心 RAG 环路(单路 · 流式 · 回证) 实现

## What
上传小 PDF/MD → 解析+三段分块+LLM 抽 item_name 拼头+embed+Milvus 入库 → 中文问 → 单路 dense top-N 召回 → LangGraph 状态机 → LLM 生成带 citation 答,流式推前端。三轮对话带历史。

## 本期范围(ISSUE 02 收紧)
- 单路 dense:ISSUE 02 原 AC 只要求"单路 · 流式 · 回证"。三路 RRF 拓扑保留(fuse 节点仍在,route3 占位空列表即兼容),但 Milvus hybrid_search/route1 由 LangGraph retrieve 单节点驱动,单 query 只做一次 embed+hybrid_search。
- embed/rerank 离线可跑 fallback:无 sentence_transformers 用 BM25-style sparse + HashingVectorizer-style deterministic dense + overlap-coefficient rerank。
- LLM 默认 Stub(LLM_STUB=1),测试期全离线。

## 工程要点
- VectorStore 抽象(app/storage/vector_store.py):MilvusVectorStore(pymilvus 3.x MilvusClient API)+ InMemoryVectorStore(测试兜底)+ 连不上时自动降级。
- 入库管线(app/ingestion/pipeline.py):parse_document → chunk_document 三段(item_name 已拼头) → embed → Milvus+Mongo。
- LangGraph(app/graph/pipeline.py):单节点 retrieve 即做 hybrid_search + RRF + rerank + 路由决策(拒绝/本地/网搜),不调 LLM。/api/query 的 streaming handler 自己做单次 LLM astream,避免双 LLM 调用。
- RRF 三路:在 retrieve 节点里合并 route1/route2/route3(RRF score(d)=Σ 1/(k+rank+1)),兼容后续接 MCP 路3。
- /api/query SSE:event=meta(含 citations+route+trace) → event=token(多次) → event=done。reject 路径不调 LLM。

## Known limitations(MVP 显式文档化)
- Milvus hybrid_search 用内建 RRF 重排,α 参数仅作用于 InMemoryVectorStore(Milvus 路径文档化于 vector_store.py:259)。
- embedder fallback 用 HashingVectorizer + BM25 IDF;无 GPU/无 sentence_transformers。真实部署需安装 sentence_transformers 并在 .env 里关 EMBED_FALLBACK/RERANK_FALLBACK。
- LLM 默认 Stub;真实部署需在 .env 里填 LLM_API_KEY 并关 LLM_STUB。
- PyMuPDF 装 fitz,但默认 font 不含 CJK。生产 PDF 入库前需内置 CJK font 的 PDF 或先 OCR。
- MilvusVectorStore 连不上时降级 InMemoryVectorStore,无跨重启持久性。
- _MongoDocs 在 motor 连不上时降级进程内存根,重启丢失 metadata。
